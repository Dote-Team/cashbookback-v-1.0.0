# تشغيل النظام بـ Docker — دليل عملي

> هذا الدليل خاص بالمشروع الخلفي (`d:\cashbook_back-master`).
> الواجهة الأمامية مشروع منفصل يُبنى ويُنشر بطريقته.
> كل الأوامر تُنفَّذ من مجلد المشروع.

---

## 1. الملفات المُضافة ووظيفة كل واحد

| الملف                | الوظيفة                                                                      |
| -------------------- | ---------------------------------------------------------------------------- |
| `Dockerfile`         | بناء صورة الإنتاج من مرحلتين: البناء بـ SDK، والتشغيل بخادم ASP.NET Core فقط |
| `Dockerfile.migrate` | صورة «أدوات» لإنشاء جداول قاعدة البيانات (EF Core) — تُستعمل مرة واحدة       |
| `docker-compose.yml` | تشغيل الواجهة + قاعدة بيانات SQL Server + الشبكة + الأقراص الدائمة           |
| `.dockerignore`      | يمنع إرسال `bin/` و `obj/` و **`.env`** إلى محرّك البناء                     |
| `.env.example`       | قالب الأسرار — يُنسخ إلى `.env` (وهو مُستثنى من Git)                         |

**لا سرّ واحد مكتوب داخل الصورة.** كل القيم الحسّاسة تُقرأ وقت التشغيل من `.env`.

## 2. قبل أن تبدأ

على الخادم (أو جهازك) يجب توفّر:

```bash
docker --version           # Docker Engine 24 أو أحدث
docker compose version     # Compose v2
```

الحد الأدنى المقترح للموارد: **2 نواة و 4 غيغابايت ذاكرة** إن كانت قاعدة
البيانات داخل Docker؛ وزوج النواة والغيغابايت الواحد يكفي مع قاعدة بيانات خارجية.

## 3. النشر — أربع خطوات

### أ) انسخ المشروع وأنشئ ملف الأسرار

```bash
copy .env.example .env        # ويندوز
cp   .env.example .env        # لينكس
```

ثم حرّر `.env` واملأ **بالإلزام**:

- `MSSQL_SA_PASSWORD` — كلمة مرور قوية لحساب `sa` (حرف كبير + حرف صغير + رقم + رمز، 8 خانات على الأقل، وإلا رفضت صورة SQL Server الإقلاع).
- `ApiSettings__Secret` — مفتاح توقيع خاص بالخادم. ولّده بعد الخطوة (ب) بالأمر:
  ```bash
  docker run --rm --entrypoint dotnet cashbook-api:latest cashbook.dll --generate-secret
  ```
- `ConnectionStrings__DefaultConnection` — إن كانت قاعدة البيانات في Docker فالقيمة الجاهزة في القالب صحيحة بشرط أن تبدّل كلمة المرور فيها بنفس `MSSQL_SA_PASSWORD`.
- `CorsSettings__AllowedOrigins__0` — نطاق الواجهة الفعلي **بلا شرطة أخيرة**، وإلا رفض المتصفح كل نداء.

> التطبيق **يرفض الإقلاع** إن كان `ApiSettings__Secret` فارغاً أو أقصر من 32 حرفاً — وهذا مقصود.

### ب) ابنِ الصور

```bash
docker compose build
```

### ج) أنشئ جداول قاعدة البيانات (مرة واحدة عند أول نشر، وبعد كل ترحيل جديد)

```bash
docker compose --profile tools run --rm migrate
```

هذه الصورة تبني المشروع وتشغّل `dotnet ef database update`، ثم تختفي (`--rm`).
الصورة الإنتاجية لا تحتوي مترجماً ولا أداة `dotnet-ef`، فلا تستطيع إنشاء الجداول بنفسها.

### د) شغّل النظام

```bash
docker compose up -d
docker compose ps
```

## 4. التأكد أنه يعمل

من داخل الخادم:

```bash
curl -i http://localhost:5003/API/Files/none.png     # المتوقّع: 404 (الخادم يعمل)
docker compose logs -f api                            # لمتابعة السجل مباشرة
```

فحص الحاوية نفسها:

```bash
docker inspect --format '{{.State.Health.Status}}' cashbook-api    # healthy
```

من جهاز آخر على الشبكة استبدل `localhost` بعنوان الخادم.

## 5. أول حساب في النظام

قاعدة البيانات تُنشأ **فارغة** عمداً (لا بيانات تجريبية). الترتيب الصحيح:

1. أنشئ أول حساب:
   ```
   POST http://<الخادم>:5003/API/User/register
   { "username": "admin", "password": "<8 أحرف على الأقل بحرف ورقم>", "name": "<الاسم>" }
   ```
2. اكتب `AdminUser__Username=admin` في `.env`.
3. أعد تشغيل الواجهة فقط: `docker compose up -d api`
   عند الإقلاع يُمنح الحساب صلاحية المدير الرئيسي تلقائياً.

التفاصيل الكاملة في `GO-LIVE.md`.

## 6. أوامر يومية

```bash
docker compose logs -f api        # السجل الحيّ
docker compose restart api        # إعادة تشغيل بعد تعديل .env
docker compose down               # إيقاف (البيانات تبقى في الأقراص الدائمة)
docker compose up -d --build      # نشر نسخة جديدة من الشيفرة
docker compose ps                 # الحالة
```

النسخ الاحتياطي لقاعدة البيانات:

```bash
docker exec cashbook-db /opt/mssql-tools18/bin/sqlcmd -C -S localhost -U sa \
  -P "<MSSQL_SA_PASSWORD>" -Q "BACKUP DATABASE [cash] TO DISK='/var/opt/mssql/cash.bak'"
docker cp cashbook-db:/var/opt/mssql/cash.bak ./cash.bak
```

الأقراص الدائمة: `cashbook-mssql-data` (قاعدة البيانات) و `cashbook-uploads`
(صور المرفقات). `docker compose down` لا يمسحهما، و`down -v` **يمسحهما** — لا تستخدمه.

## 7. قرارات مهمّة تناولها هذا الإعداد

**الحاوية تعمل بمستخدم غير جذري.** صورة `aspnet:8.0` فيها المستخدم `app` (uid 1654)،
والملف ينسخ الملفات بمالكه (`COPY --chown=app:app`) ثم يُنهي بـ `USER app`.
السبب: لو نُفّذت ثغرة تنفيذ عن بعد ووصل المنفّذ إلى الحاوية، وجد نفسه بلا صلاحيات
جذر. وملف المرفقات يُملَّك لـ `app` عمداً، لأن أول إنشاء للـ volume ينسخ صلاحيات
المجلد من الصورة، فإن كان ملكه الجذر عجز التطبيق عن الكتابة فيه.
ملاحظة: استعمل `--chown` في `COPY` ولا `chown -R` بعدها، لأن الثاني ينسخ
كل ملف في طبقة جديدة فيضاعف حجم الصورة.

**الخادم ينصت على 8080 داخل الحاوية.** `appsettings.json` يثبّت Kestrel على
`http://localhost:5003`، أي على واجهة الاسترجاع داخل الحاوية فقط. الصورة تتجاوز
ذلك بالمتغيّر `Kestrel__Endpoints__Http__Url=http://+:8080` (متغيّرات البيئة تغلب
ملفات الإعداد). المنفذ الظاهر على الخادم هو `5003` وهو ما تتوقّعه الواجهة
(`BASIC_URL=http://<الخادم>:5003/`) — غيّره بـ `API_PORT` في `.env`.

**مجلد `wwwroot/uploads` قرص دائم.** بدونه تُفقد صور المرفقات عند كل إعادة بناء.

**ترتيب الحروف `SQL_Latin1_General_CP1_CI_AS` مثبّت صريحاً.** البحث بـ
`CHARINDEX` وفهرس اسم المستخدم الفريد يعتمدان على عدم التمييز بين الحالة (CI).

**المنطقة الزمنية `Asia/Baghdad`.** بداخلها افتراضياً بتوقيت UTC، والنظام يستخدم
`DateTime.Now` في التواريخ وسجل التدقيق. غيّرها في `docker-compose.yml`.

**النظام يعمل في بيئة `Production`.** لتُتيح صفحة Swagger لفريق الواجهة مؤقتاً،
أضف إلى `.env`:

```
ASPNETCORE_ENVIRONMENT=Development
```

ثم `docker compose up -d api` — وافتح `http://<الخادم>:5003/swagger`.
لا تُترك على `Development` في الإنتاج.

**⚠️ لا تشغّل الصورة بزر Run في Docker Desktop ولا بـ `docker run` مجرّداً.**
زر Run لا يمرّر أي متغيّر بيئة (ولا يقرأ `.env`)، فتخرج حاوية باسم عشوائي وتنهار
فوراً بخطأ المفتاح، وتظهر في قائمة Containers كـ `Exited`. وكذلك صورة
`cashbook-migrate` ليست للتشغيل من الزر — هي أداة تعمل مرة واحدة بأمر محدّد.
ولمن يريد التشغيل اليدوي رغم ذلك، هذه هي المتغيّرات المطلوبة (نفس ما يفعله compose):
ملف `.env` عبر `--env-file`، أو في نافذة Run: `ApiSettings__Secret`
و `ConnectionStrings__DefaultConnection` ولاحظ أن اسم الخدمة `db` **لا يُحل** خارج
شبكة compose، فاستعمل `Server=host.docker.internal,14330` بدلاً منه، واربط المنفذ
`5003 ← 8080`.

**منفذ قاعدة البيانات `14330` منشور على الشبكة** (وليس 1433، حتى لا يتعارض مع
خادم SQL آخر على الجهاز نفسه). في الإنتاج الحقيقي علّق السطر في `docker-compose.yml`
واترك الحاويتين تتخاطبان على الشبكة الداخلية وحدها — الحاوية تتصل بخدمة `db`
بالاسم لا بهذا المنفذ.

**عندك قاعدة بيانات جاهزة؟** احذف خدمة `db` من `docker-compose.yml`، املأ سلسلة
اتصالها في `.env`، ثم:

```bash
docker compose up -d --no-deps api
docker compose --profile tools run --rm migrate   # إن كنت تريد تطبيق الترحيالات
```

**HTTPS.** الحاوية تتكلّم HTTP فقط. إن أردت HTTPS ضع أمامها وسيطاً عكسياً
(nginx / Caddy / Traefik) يتولّى الشهادة، أو استخدم موازن تحميل مُدار من مزوّد
الاستضافة. إجبار HTTPS للإعادة التوجيه لا يتم داخل التطبيق.

## 8. حلّ المشكلات

| الأعراض                                                                      | السبب والحل                                                                                                                     |
| ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | --- | --------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --- | --------------------------------------------- | ----------------------------------------------------------------------------------- |
| خطأ `no configuration file provided: not found` أو `env file .env not found` | ملف `.env` غير موجود — نفّذ الخطوة 3/أ.                                                                                         |
| `Application startup exception: مفتاح توقيع الرموز … غير مضبوط`              | `ApiSettings__Secret` فارغ أو أقصر من 32 حرفاً.                                                                                 |     | نفس الخطأ والمفتاح في `.env` سليم | الصورة لا تحمل مفتاحاً بداخلها عمداً، و`docker run` المجرّد وزر **Run** في Docker Desktop **لا يقرآن** `.env`. استخدم `docker compose up -d` أو `docker run --env-file .env`. |     | الحاوية `cashbook-db` تُعاد تشغيلها بلا توقّف | كلمة مرور `sa` ضعيفة (صورة SQL Server تشترط التعقيد)، أو الذاكرة أقل من 2 غيغابايت. |
| الواجهة تعمل لكن المتصفح يرفض كل نداء                                        | نطاق غير مدرَج في `CorsSettings__AllowedOrigins__*`، أو فيه شرطة أخيرة، أو عنوان المتصفح HTTP والواجهة HTTPS.                   |
| `401` على كل الطلبات بعد إعادة تشغيل                                         | مفتاح `ApiSettings__Secret` تغيّر فصارت الرموز القديمة باطلة — سجّل الدخول من جديد.                                             |
| جداول مفقودة (`Invalid object name 'Users'`)                                 | لم يُنفَّذ `docker compose --profile tools run --rm migrate`.                                                                   |
| لا يصل شيء إلى `localhost:5003`                                              | `docker compose ps` أولاً، ثم `docker compose logs api`.                                                                        |
| تحذير `DataProtection` في السجل                                              | طبيعي: إطار العمل يخزّن مفاتيح مؤقتة داخل الحاوية. النظام لا يستخدم كوكيز ولا antiforgery (المصادقة بترويسة JWT) فلا أثر وظيفي. |

## 9. نتائج الفحص الفعلي (20 أيلول 2026)

كل ما يلي جُرِّب فعلياً على هذا الجهاز (Docker 29.3.0 / Compose v5.1.0 / linux-amd64):

| الفحص                                                     | النتيجة                                                                       |
| --------------------------------------------------------- | ----------------------------------------------------------------------------- |
| `docker compose config`                                   | صحيح                                                                          |
| `docker compose build api`                                | ناجح — صورة `cashbook-api:latest` بحجم 375 ميغابايت                           |
| `docker compose up -d db`                                 | الحالة `healthy` بعد ~30 ثانية                                                |
| `docker compose --profile tools run --rm migrate`         | أُنشئت قاعدة `cash` وفيها **17 جدولاً**                                       |
| `docker compose up -d api`                                | الحالة `healthy` خلال ~10 ثوانٍ، `5003 -> 8080`                               |
| `GET /`                                                   | `404` — طبيعي، لا مسار جذر في هذه الواجهة                                     |
| `POST /API/User/register`                                 | **`201 Created`** ومعرّف مستخدم حقيقي من قاعدة الحاوية                        |
| هوية العملية داخل الحاوية (`docker exec cashbook-api id`) | `uid=1654(app)` — **ليس الجذر**                                               |
| الكتابة في مجلد المرفقات                                  | `touch` نجح والملف صار ملك `app:app`                                          |
| **إصلاح 409 الكاذبة** (20 أيلول) — قاعدة البيانات متوقفة  | `200` و `isSuccess=false` برسالة عامة، وسُجّل `SqlException` الحقيقي في السجل |
| نفس الطلب وقاعدة البيانات تعمل                            | **`201 Created`**                                                             |
| `hadolint` على `Dockerfile`                               | بلا تحذيرات (يتبقّى تنبيه معلوماتي وحيد: يُفضّل `USER 1654` بدلًا من الاسم)   |
| تصدير الصورة                                              | `cashbook-api.tar` بحجم 100 ميغابايت، بصيغة `manifest.json` الكلاسيكية        |

> أوّل بناء على هذا الجهاز استغرق وقتاً طويلاً لأن صور `dotnet/sdk:8.0` و `dotnet/aspnet:8.0`
> لم تكن موجودة محلياً (~1 غيغابايت على شبكة بطيئة). بعدها صار البناء يستعمل الذاكرة المؤقتة.

## 10. صورة جاهزة للنقل (خادم بلا إنترنت بطيء)

بجانب بناء الصورة على الخادم، يمكن نقل صورة جاهزة:

```bash
docker load -i cashbook-api.tar      # على الخادم
```

ثم شغّلها بالطريقة التي تناسبك: `docker compose up -d --no-deps api` (بعد تجهيز `.env`
وسلسلة الاتصال بخادم قاعدة بيانات يصل إليه)، أو يدوياً:

```bash
docker run -d --name cashbook-api --restart unless-stopped \
  -p 5003:8080 \
  --env-file .env \
  -v cashbook-uploads:/app/wwwroot/uploads \
  cashbook-api:latest
```

> في الحالتين يجب أن تكون `ConnectionStrings__DefaultConnection` في `.env` تشير
> إلى `db,1433` إن كانت قاعدة البيانات في شبكة Docker نفسها، أو إلى عنوان خادم
> قابل للوصول من داخل الحاوية (`localhost` داخل الحاوية تعني الحاوية نفسها، لا الخادم).
>
> الملف المُصدَّر يحتوي **صورة الواجهة فقط**. صورة SQL Server تُسحب من الإنترنت
> عند `docker compose up -d db`، وصورة أدوات الترحيالات تُبنى عند الحاجة.

ملف جاهز على سطح المكتب في مجلد `cashbook-docker-deploy\` بجانب `docker-compose.yml`
و `.env.example` و `cashbook-schema.sql` و `INSTALL.md` و سكربتي `setup-env`.
الصورة (`cashbook-api.tar` · 100 ميغابايت · SHA256:
`A0235632F5B5FE7700D487C2E8FE3BAAF330780F3E815545BCB6EF35F1997DE3`)
مبنية لـ `linux/amd64` ومُحصّنة بتشغيل غير جذري — أي خادم لينكس حديث يستوعبها.
